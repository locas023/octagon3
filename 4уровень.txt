Описание

Локальных и учебных API больше недостаточно. На этом уровне появляется собственная база данных, серверные endpoints, авторизация и роли. Сервер должен сам проверять доступ к данным и бизнес-правилам, независимо от того, что показывает UI.





Необходимо реализовать

подключить PostgreSQL и описать схему основных сущностей;
реализовать server/api для auth, requests, users, customers, categories и comments;
добавить seed-данные для локальной разработки;
реализовать login, logout и пользовательскую сессию;
реализовать роли Client, Operator, Agent и Admin;
реализовать создание и изменение заявок через server API;
реализовать правила переходов статусов заявок;
проверять права доступа на сервере для каждой защищённой операции;
вынести действительно общие типы и utilities в shared/;
не допускать импорта app-only кода в server и server-only кода в app.




Требования

Nuxt 4 + Nitro;
PostgreSQL;
TypeScript;
типобезопасная валидация входных данных через Zod или эквивалент;
серверная авторизация, а не только скрытие кнопок в интерфейсе;
запрет выдачи приватных данных неавторизованным пользователям;
Client не может получить чужую заявку прямым API-вызовом;
Agent не может выполнять административные действия;
нельзя назначить деактивированного пользователя исполнителем;
осмысленные HTTP status codes для ошибок API.
