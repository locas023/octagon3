# Регрессии

1. Быстрый двойной клик «Отправить»: два комментария. Причина — конкурентные запросы без ключа. Исправление: pending в UI, уникальный ключ в БД; integration/api.mjs отправляет два запроса одновременно и проверяет один комментарий.
2. Быстрый поиск A → B с медленным A: старый ответ заменяет новый. useFetch с отменой предыдущего запроса и query watcher владеет результатом. Проверено E2E с задержкой старого ответа; debounce unit проверяет последнее значение и отмену таймера при уничтожении scope.
3. Logout → прямой переход /requests: доступ к кэшу. Middleware проверяет серверную сессию каждый переход; logout очищает Nuxt cache. API integration проверяет 401, E2E проверяет переход на login.
4. Refresh сбрасывал фильтры и плотность. Фильтры читаются из URL; preferences загружаются после hydration. Два отдельных E2E подтверждают сохранение.
5. PATCH заявки возвращал пустые комментарии, поскольку они лежат в отдельной таблице. Теперь ответ повторно читает комментарии в транзакции; API regression проверяет сохранение после изменения приоритета.
6. Profile сохранял локальную копию и выходил без отзыва сессии. Добавлен серверный PATCH профиля, logout вызывает сервер. E2E проверяет refresh, сохранение и последующий 401.
7. Optimistic priority мог остаться в UI после отказа сервера. E2E удерживает PATCH, проверяет немедленное изменение badge, затем rollback при 409/500 и успешный Undo следующего изменения.
8. Сериализация вложенных proxy-объектов в JSONB давала некорректные данные. На границе SQL создаются обычные структуры; основной workflow и API тест проходят на production Docker.

E2E необходимо запускать с работающим сервером и seeded БД. Непройденные проверки не считаются выполненными.
