Описание

На этом уровне список и карточка заявки начинают получать данные с API. Состояние поиска и фильтрации должно быть связано с URL, а интерфейс — корректно работать во время загрузки, при пустом ответе и при временной ошибке сервера.





Необходимо реализовать

подключить GET /api/requests, /api/users, /api/customers и /api/categories;
перевести список и страницу заявки на useFetch/useAsyncData;
добавить поиск, фильтрацию, сортировку и pagination через query-параметры;
синхронизировать фильтры с URL;
добавить debounce для поиска;
реализовать skeleton loading, empty state и error state;
добавить возможность повторить запрос после временной ошибки;
описать модели API TypeScript-типами без any в ответах API;
вынести преобразование данных из API в одно место, а не дублировать его по компонентам.




Требования

Nuxt 4 data fetching: useFetch/useAsyncData;
TypeScript-типы для API-моделей;
debounce для поиска без запроса на каждый введённый символ;
восстановление состояния страницы по query-параметрам прямой ссылки;
обработка HTTP 429 и 500 с понятным сообщением и повторным запросом;
отдельное состояние empty state при отсутствии результатов;
устойчивое отображение списка при отсутствии необязательного поля в отдельной записи.
