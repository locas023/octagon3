Описание

WorkFlow уже получает реальные данные. Теперь пользователь должен уметь изменять заявку: менять приоритет, статус и исполнителя, добавлять комментарии. Для быстрых действий нужно применить optimistic update и уметь вернуть состояние назад при ошибке API.





Необходимо реализовать

добавить Pinia только для состояния, которым пользуются несколько частей приложения;
реализовать изменение статуса, приоритета и исполнителя;
реализовать добавление комментария;
сделать optimistic update для изменения приоритета;
при ошибке API выполнять rollback к предыдущему значению;
добавить Undo для последнего изменения статуса или приоритета;
сохранять пользовательские настройки интерфейса локально;
определить, какие данные относятся к URL state, local state, server state и app state;
не объединять всю предметную область в один глобальный store.




Требования

мгновенное отображение optimistic update в интерфейсе;
понятное сообщение о причине rollback при ответе 409 или 500;
восстановление предыдущего значения через Undo как минимум для последнего изменения;
сохранение URL-фильтров и пользовательских UI-настроек после обновления страницы;
единый источник для каждого состояния без необоснованного дублирования;
изменение состояния без необходимости переписывать компоненты-потребители.
