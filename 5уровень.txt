Описание

Теперь задача состоит не только в добавлении функциональности. Нужно научиться воспроизводить проблемы, находить root cause и фиксировать регрессии автоматическими тестами. В работе появляются асинхронные гонки и полный E2E-сценарий пользователя.





Необходимо реализовать

для каждого найденного бага описать шаги воспроизведения и предполагаемую причину;
исправить двойную отправку комментария;
исправить ситуацию, когда устаревший ответ поиска перезаписывает более новый результат;
исправить доступ к приватному route после logout;
исправить потерю или рассинхронизацию состояния после refresh;
обработать сценарии API 500, 401 и 409;
добавить unit/integration-тесты для бизнес-правил и composables;
добавить Playwright E2E-сценарий login → create request → assign → change status → comment → logout;
добавить regression test для каждого исправленного бага.




Требования

проверка ожидаемого поведения вместо привязки тестов к внутренней реализации компонентов;
воспроизводимый сценарий и автоматический regression test для каждого исправленного бага;
прохождение критических E2E-сценариев в чистом окружении;
независимость тестов от случайных таймингов и нестабильных внешних условий;
успешное прохождение typecheck и lint после исправлений.
